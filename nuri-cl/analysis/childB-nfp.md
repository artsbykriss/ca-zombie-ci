## 2. Fresh-attacker claim / pool-poisoning analysis (task 2)

- **Can a fresh attacker mint cheaply?** Yes — `NFP.mint` on any initialized pool; observed real txs cost 363k–945k gas at 0.12 gwei (≈$0.05–0.11). But a fresh NFT only gives rights over itself. Farming gauge emissions pro-rata to (liquidity × seconds-in-range) is legitimate, not extraction.
- **Direct `pool.mint(recipient=NFP_manager, index=<fake>, ticks, …)`**: `ClPool.mint` is permissionless and allows arbitrary `recipient`/`index` (callback goes to the caller, who pays). **Refuted as an exploit**: (a) the gauge derives the position hash from `nfpManager.positions(tokenId)` → `positionHash(NFP, tokenId, NFT's ticks)`, so attacker-chosen ticks map to an unreachable hash; (b) creating liquidity at the *real* `(NFP, tokenId, ticks)` key is just gifting liquidity to that NFT's pool position, and every payout path pays `ownerOf(tokenId)`; (c) the gauge's own `getReward(owner=NFP,index,…)` variant requires `msg.sender == NFP` (impossible). Pool `burn`/`collect` use `owner=msg.sender`, so third parties cannot touch the NFP's pool positions.
- **Past-period claims by a new position (checkpoints)**: `Position.positionPeriodSecondsInRange` returns 0 when `checkpoints.length==0` or when the first checkpoint period > requested period (`getCheckpoint` → `(0,0)`). A position minted in period P cannot claim P−1. Current period claim is pro-rated from mint time (`initializeSecondsStart` sets `secondsPerLiquidityPeriodStartX128` at first touch; debt handles pre-existing liquidity). Verified by reading Position.sol/GaugeV2.sol; not reproduced on-chain (no attacker position needed — code path is deterministic).
- **`GaugeV2.cachePeriodEarned(…,caching=true)` is public**: it can write `periodAmountsWritten/periodNfpSecondsX96` for any `(period<current, owner,index,tl,tu)`. Not exploitable: the cached value is the pool-computed true value for that exact tuple at cache time; for past periods the pool data is frozen (pool writes to `periodRewardInfo[P]`/checkpoints only while P is the current period), and the claim path only reads hashes derived from the real NFT (same tuple). Staticcall failure → 0, never a credit.
- **Live sims (attacker)**: `Gauge.getRewardForOwner(67113,…)`/`getReward(owner,index…)`/`getReward(67113,…)`/`getPeriodReward(…)` → all `Not authorized`. `Voter.claimClGaugeRewards([gauge],[tokens],[[67113]])` → revert (it re-checks `nfpManager.ownerOf/getApproved`; note it then calls `IFeeDistributor(gauge).getRewardForOwner` — passing a GaugeV2 address makes the *Voter* the authorized caller, but the gauge still pays `ownerOf(tokenId)`, i.e. the owner). `FeeDistributor.getRewardForOwner` requires `msg.sender == voter` and pays `veNFT.ownerOf(tokenId)`.

## 4. Verdict

- **E-U (external unprivileged) today from NFP/veNURI surfaces: $0 — high confidence.** Every value-moving entry point on the NFP, GaugeV2, Voter passthrough and VotingEscrow is owner/approved-gated; the NFP and all Nuri contracts hold no sweepable/claimable balances; no contract-owned positions/veNFTs are reachable by third parties (Sickle model verified fixed).
- **Latent (not E-U today):** (1) NFP `sweepToken`/`unwrapWETH9`/`refundETH` will hand any future NFP balance to the first caller — monitor/avoid `collect(recipient=0)` and unrefunded mint ETH; (2) gauge rewards are paid to the NFT owner at claim time (no checkpointing on transfer) — buyers of positions with unclaimed rewards lose them; (3) NURI has no meaningful exit liquidity, so the "$24.6k locked / $2.8k gauge rewards" are book figures only.
- **Negatives/dead ends recorded:** NFP-owned NFTs (none), pool-position poisoning via fake index (unreachable hash / gift-only), direct `pool.burn|collect` for foreign owners (impossible: owner=msg.sender), gauge cache poisoning (`cachePeriodEarned` caching), past-period claims by new positions (checkpoint → 0), Minter reinit takeover (consumed), Minter mint path (NURI `!MINTER`, commandCenter role-gated), Sickle pre-seeding (internal `getOrDeploySickle`; factory whitelist), NFP XToken `rescueTrappedTokens` (reverts `xToken: !Auth`), RewardsDistributor claim (reverts `ve !AUTH`).
